# 02 目标与非目标

- 版本：v0.8-draft（2026-08-18）
- 上级文档：[README.md](README.md)

## 1. 目标

### G1 产品目标

做一个**单用户桌面安装版** AI Agent 应用（BC Agent Desktop）：

1. 用户提供自研的完整前端界面（manus.im/app 风格），计划功能保留并以真实数据运行：**技能、定时任务、工作区（原「工作事项」，含原「普通任务」——会话均在工作区内，首次启动必须手动选择工作区，否则不工作）、色调、规则管理、记忆管理**
2. 完整继承 dsh 现有功能：会话（流式对话/工具调用/审批交互/plan 模式）、技能调用、设置、凭证、模型管理、子代理、上下文压缩等——通过嵌入官方对话组件与设置页实现
3. 交付形态：Windows 优先（NSIS 安装包），macOS 后置；本地数据，**数据不出本机**
4. **开源发布**
5. **白标可配置**：源码发布时通过单一品牌配置（`branding/`：名称/图标/安装包/更新源）生成不同企业品牌版；代码标识符与数据路径不随品牌变化（机制见 [03-architecture.md §9](03-architecture.md)）
6. **中英双语（zh/en）**：界面完整支持中文/英文切换——官方组件随官方 `locale` 偏好自动切换，bc 自研外壳/页面同步双语（机制见 [03-architecture.md D14](03-architecture.md) 与 [04-spec.md §3.11](04-spec.md)）

### G2 工程目标（与产品目标同等重要）

1. **上游核心零修改**：不 fork、不打 patch 到上游源码；所有定制通过标准插件 + profile 叠加实现
2. **升级适配成本最小化**：上游 dsh 迭代很快（预发布期），本项目的代码结构必须保证「改版本号 + 跑冒烟清单」即可完成一次升级
3. 与 `demo/deepseek-harness-desktop` 的架构纪律对齐：npm 依赖锁定、loopback-only、不污染系统环境

### G3 演进目标（后置，不在本期范围）

单用户版稳定 + 企业出现实际定制需求后，演进多用户版。届时：

- 复用 v0.8.1 的组织/认证/审核设计，以及**工作区企业定制**（core_duty/work_style/workflow 三段 AI 行为定义 + 创建期技能绑定——v0.4 从单用户版移除，届时经 system-prompt 接缝注入）
- 本期数据模型预留低成本扩展字段（见 [04-spec.md §4.7](04-spec.md)），避免硬迁移
- **已知迁移成本（v0.5 记录）**：多用户期工作区数据需从上游 workspaceRegistry（本地 `ctx.storage`，无迁移承诺）迁到企业 PG 的 projects 表，届时需一张「上游 WorkspaceId ↔ 企业侧 id」映射表并做导出/导入——本期提供的业务数据导出工具（备份/恢复，见 §4 发布标准）应覆盖工作区薄表，为该迁移预留通道

## 2. 非目标（本期明确不做）

| 非目标 | 理由 |
|---|---|
| 多用户/租户/组织架构 | 无实际需求；部署/服务器成本高（用户决策）。v0.8.1 自身也已确认单企业部署即可 |
| 认证/登录（authserver/JWT） | 单用户本机应用无认证需求 |
| 管理后台（frontend-admin） | 管理功能合并进用户端设置页 |
| AgentScope 2.0 集成 | 被 dsh 完全替代（用户决策） |
| 服务器部署形态（Nginx/ELK/K8s/监控全家桶） | 桌面单机版不需要 |
| 云端记忆服务（Mem0/Qdrant） | 数据不出本机原则；自建 SQLite 记忆 |
| 技能审核流（pending/approved/rejected 状态机）、部门/人员分配范围 | 单用户无意义；数据模型保留字段，UI 简化 |
| 自由任务（无工作区绑定的会话） | 纯聊天走 DeepSeek 官网（免费、不耗 token）；本产品定位是「干活」，每个会话都应在工作区上下文中（v0.2 用户决策）。会话必须显式选择工作区，无「默认工作区」兜底（v0.8 用户决策） |
| 库（跨会话文件归集视图） | 单机版本就是本地文件操作，跨会话归类多此一举；本期不做，完成后另做方案（v0.7 用户决策） |
| 知识库 | 上传/录入类知识库价值有限；基础版完成后单独规划（v0.7 用户决策） |
| 自研对话区（消息流/工具渲染/审批 UI） | 复用官方 conversation slot；后期可逐块替换 |
| 手机端/远程访问 | 后置（dsh 桌面参考项目同样后置此功能） |
| 插件市场 | dsh 社区市场本身未落地；本期仅支持 `dsh plugin` CLI 管理插件 |
| macOS/Linux 正式发布包 | Windows 优先；mac 冒烟（未签名 DMG）后置，Linux 仅兼容模式不承诺 |

## 3. 约束

| # | 约束 | 来源 |
|---|---|---|
| C1 | 上游 `@deepseek-ai/dsh-*` 以 npm 锁定版本引入，禁止修改其源码 | G2 |
| C2 | 所有定制以 dsh 插件（Host 插件 + `dsh.client` 浏览器插件）+ bundle patch 形式实现 | G2 |
| C3 | webserver 仅绑定 loopback（`127.0.0.1`）；renderer `contextIsolation` + sandbox，无 Node 集成 | 参考项目安全纪律 |
| C4 | 业务数据存本机（`ctx.storage` / 插件自有 SQLite），不上传 | v0.8.1「数据不出服务器」→「数据不出本机」 |
| C5 | 前端框架对齐官方客户端运行时（React 18.x）；自研前端需从 React 19 降级 | 官方声明 `^18.2.0`（实际解析 18.3.1，以锁定版本的 `pnpm ls react` 为准）；插件与其共享运行时 |
| C6 | 模型可见的注入内容（规则/记忆）必须可从会话日志重建（dsh 铁律「model-visible ⟺ logged」） | 上游 AGENTS.md；v0.5 确认由官方接缝天然满足（section → `request/header.header.system`；context → runtime-context `user/message` 快照） |
| C7 | 定时任务依赖桌面进程存活（无系统级 cron/守护）；产品需明示此限制 | 上游无系统调度器 |
| C8 | 开源合规：上游及依赖 License 审查、THIRD_PARTY_NOTICES | 开源发布要求 |
| C9 | 品牌版之间数据隔离：各品牌版默认使用独立 `DSH_HOME`（v0.5） | 白标多企业场景下品牌间数据/凭证不可混居；共享 `~/.dsh` 需显式 opt-in |
| C10 | 中英双语实现对齐上游 locale 框架（v0.6）：bc 自研文案经 `ctx.locale.register(ns, { zh, en })` 注册、渲染走 `t` seat；zh 为 key 集事实源、en 编译期校验双语平衡；**用户内容（会话/记忆/规则正文）不做机器翻译** | 上游 `dsh-client-locale` 已内置双语框架，官方组件零成本；用户数据原样保存避免翻译失真 |

## 4. 成功标准

**发布标准（P5 验收）：**

1. `BC-Agent-Desktop-Setup.exe` 全新安装后开箱即用：无需预装 Node/pnpm/Python；DeepSeek API key 走应用内设置保存
2. 全部计划功能以真实数据可用（对照 [04-spec.md §2](04-spec.md) 的功能清单；「自由任务」已并入工作区模型，v0.2）
3. 官方对话区完整可用：流式输出、工具调用渲染、审批交互、plan 模式、用户问答
4. **升级演练通过**：模拟一次上游 minor 升级（改版本号 → 安装 → 跑冒烟清单 → 通过），全程不修改上游源码；**演练必须包含旧版本产生的会话日志在新版本可读的回归项**（R13）与 storage domain 版本演练（S8）
5. 卸载干净：不残留系统 PATH 修改、不留全局服务；数据目录（独立 `DSH_HOME`）默认保留，卸载器提供「同时删除数据」可选项
6. 白标验证：用示例品牌配置从同一源码产出一个改名版安装包，S7 产物扫描（grep 脚本）无默认品牌残留
7. 备份/恢复可用：业务数据（`DSH_HOME` 全量 + 自有 SQLite 库）可一键导出为归档并从归档恢复（P5 交付；同时服务多用户期迁移，见 G3）
8. **中英双语验收（S10）**：zh↔en 切换后，bc 自研外壳/页面文案无中文残留（en 态）且无缺失 key（fail-loud 不出现原文 key）；官方会话/设置组件跟随切换

**工程标准（贯穿各期）：**

- 前端对上游的调用收在 `src/adapters/upstream.ts` 单点；Host 侧插件只消费文档化 `ctx.*` 服务，触点清单进升级 PR 模板（见 [03-architecture.md §7](03-architecture.md)）
- 每期有可独立验收的产出（见 [04-spec.md §8](04-spec.md)）
- 业务插件有行为测试；关键链路（会话创建/归组/定时触发/注入可重建）有冒烟脚本
