# P0-4 spike：工作区机制确认（S6 可行性，D7 依赖链路）

- 版本：v1（2026-08-18，P0-4 产出）
- 上游事实来源：`reference/upstream`（git SHA `99f6f02f`，npm `0.1.0-rc.7`，与 `upstream.json` 一致）。文中路径均相对 `reference/upstream/`，引用给到**文件级**（行号易漂，以该 SHA 的文件内容为准）。
- 结论先行：**S6 成立、D7 纯转发成立**。`workspace.create({path})` → `session.create({workspaceId})` → 会话 cwd = 工作区目录（canonical 路径，逐字节等于注册表记录的 `path`）→ 该目录 `.agents/skills/` 下项目技能出现在该会话的 `skill.list`——全链路上游原生，bc 薄层可纯转发。同名项目覆盖用户级（rank 200 < 400）与 watcher 刷新一并实证。两个语义 surprise 见 §5。

## 1. 链路的源码事实（文件级出处）

### 1.1 workspace.create：创建即绑定 canonical cwd

- `packages/workspace/workspace/src/index.ts`（`WorkspaceRegistry`）：`create(path, title?)` 先 `realpathNormalize(path)` 规范化、校验为目录，重复同路径返回既有实体；`createCanonical` 写入 `WorkspaceRecord { path: canonical, title, sessionIds, createdAt, updatedAt }`——**canonical path 是注册表的成员资格事实源**。文件内 TODO 注明 `title` 的最后一个生产调用方（网关 create-by-name 分支）已删除——RPC 面只剩 `path`。
- `packages/host/apiproxy/src/api/workspace.schema.ts`：`workspace.create` 请求 payload **只有 `path: z.string()`**（多余键被 zod strip；PM 早前实测的 `{path, name}` 之所以"能用"，是 `name` 被静默丢弃，标题自动取 `basename(path)`）。响应 value 为 `{ workspace: WorkspaceView, created: boolean }`，其中 `WorkspaceView = { workspaceId, path, title, sessionIds, createdAt, updatedAt }`——**workspaceId 在 `value.workspace.workspaceId`**，不是裸值。
- `packages/host/apiproxy/src/api-proxy.ts`（workspace 域 + `ensureWorkspace`）：`resolveByPath` 命中则复用（`created:false`），否则 `workspaceRegistry.create(path)`，全程串行链防并发重复注册。

### 1.2 session.create({workspaceId})：cwd 取工作区 path，注册不参与技能发现

- `packages/host/apiproxy/src/api/sessions.schema.ts` + `sessions.ts`：payload `{ workspaceId?, cwd?, sessionId?, agentPreset? }`，**`workspaceId` 与 `cwd` 至多其一**（两者同传 → `bad-request`）；响应 `{ sessionId, agentPreset? }`。
- `packages/host/apiproxy/src/api-proxy.ts`（session 域 create 分支）：`const cwd = workspace?.path ?? request.payload.cwd ?? defaults.cwd`——**workspaceId 的语义就是把工作区的 canonical path 当作会话 cwd**；会话发布成功后再 `workspace.attachSession(sessionId)` 归组（失败返回 `workspace-attach-failed` 业务错误，会话已创建）。
- `packages/host/apiproxy/src/index.ts`（`ApiProxyService`）：`defaults.cwd = process.cwd()`——**不带 workspaceId/cwd 的会话落到 Host 进程 cwd**（本 spike 实测为启动目录=仓库根）。
- cwd 的验证手段（本卡采用）：`session.list` 的 `SessionSummary` 投影含 `cwd: z.string().optional()`（`sessions.schema.ts`），逐字节对照 `workspace.create` 返回的 `workspace.path`。

### 1.3 skill.list：按会话寻址，cwd 解析全在 Host 侧

- `packages/host/apiproxy/src/api/skills.schema.ts` + `skills.ts`：**入参就是 `{ sessionId }`**（必填）；文件头注释明言"会话 header 的 cwd 在 Host 侧解析为 canonical 项目根，客户端从不提交裸路径"。
- `packages/host/apiproxy/src/api-proxy.ts`（skills 域 list 分支）：`ctx.sessions.get(sessionId).header.cwd` → `skillRegistry.list({ cwd, scope })` → 过滤 user-invocable 后投影。**线上 `SkillEntry = { name, description, whenToUse?, modelInvocable }`——不含 rank/source/path**（rank 与 source 是 Host 内部 `SkillCandidate` 字段，见 §1.4；这直接约束 S6/S2b 冒烟断言只能打 name/description）。

### 1.4 skill-filesystem：rank 阶梯、SKILL.md 格式、同名覆盖

- `packages/skill/skill-filesystem/src/index.ts`：`roots(cwd)` 发现顺序与 rank——`<projectRoot>/.dsh/skills`=100（project-dsh）、`<projectRoot>/.agents/skills`=200（project-agents）、custom=300、`$DSH_HOME/skills`=400（user-dsh）、`~/.agents/skills`=500（user-agents）、bundled=600。**projectRoot 由 `findProjectRoot` 决定：从 cwd 向上找 `.git`，找到即止；一路没有则回落为 cwd 本身**（§5 surprise ②）。
- SKILL.md 格式（同文件 `parseFrontmatter`/`parseSkillFile`）：首行必须是 `---` 的 YAML frontmatter，**`name`（kebab-case `^[a-z0-9]+(?:-[a-z0-9]+)*$`，见 `packages/skill/skill/src/index.ts` 的 `SKILL_NAME`）与 `description` 必填**；可选 `whenToUse`（**字面 camelCase 键**，`parseFrontmatter` 不做键归一——写 `when-to-use` 会被静默丢弃）、`disable-model-invocation`/`user-invocable`（布尔，旧拼写如 `modelInvocable` 直接报错）、`metadata`。目录式技能为 `<root>/<name>/SKILL.md`，扁平式为 `<root>/<name>.md`；**无 frontmatter 的 .md 被静默跳过（warn 日志）**（§5 surprise ③）。
- 同名覆盖（`packages/skill/skill/src/index.ts`，`SkillRegistry.collectLayer`）：层内按 `rank asc, providerOrder, localOrder` 排序后**同名首个胜出**，后续 `warn "ignored because a higher-priority skill already exists"`——即 rank 小者覆盖 rank 大者：project-dsh > project-agents > runtime(250) > custom > user-dsh > user-agents > bundled。
- watcher（skill-filesystem 同文件，`SkillWatchManager`）：chokidar 监视项目/用户根，变更经 stability 阈值（默认 200ms）后 `invalidate()` → 注册表 revision+1 清缓存；未完成的观察（incomplete）不进缓存，天然重扫。

## 4. 对 D7 / D13 / P3b 的结论

- **D7（工作区）纯转发成立**：注册/归组/会话绑定全部官方域内闭环——`workspace.create` 的 canonical path 既是成员资格事实源又是会话 cwd 来源；bc 薄层只需（按 03-architecture §3）首次启动强制选工作区 + 以 WorkspaceId 为键的扩展元数据 KV，`workspace.*` 与 `session.create({workspaceId})` 逐字转发即可。探针 #8 进一步表明：技能可见性键控 cwd 而非注册表，D7 不引入第二事实源是安全的。
- **S6 冒烟可固化**为：`workspace.create(path)` → 造/预置 `<path>/.agents/skills/<name>/SKILL.md` → `session.create({workspaceId})` → `skill.list({sessionId})` 断言 `<name>` 在列；对照组（无 workspaceId）断言不在列。断言面只有 name/description（wire 无 rank/source，§1.3）。
- **S2b 的 rank/覆盖/watcher 三件套**本卡全部实证（#5/#6/#9），冒烟清单可直接引用 §2 的用例形状。
- **D13** 本卡未覆盖 `workspace.archiveSession`（不在本卡验收面；S2 已列，后续冒烟统一走）。
- **P3b（capability-workspace 薄层）**：无阻塞缺口；转发面 = `workspace.list/create/rename/delete/insertBefore/insertSessionBefore/archiveSession` + `session.create({workspaceId})`（adapter 单点收口 `packages/web-ui/src/adapters/upstream.ts`）。

## 5. 语义 surprises（需要 PM 知悉/定夺的）

1. **wire 面没有 rank/source/path**：`skill.list` 只回 `name/description/whenToUse/modelInvocable`。任务卡设想的"记录 rank/来源标注"在协议面不存在；来源只能靠 description 约定（本卡做法）或 Host 侧日志推断。技能管理页（capability-skillx）若要展示"项目级/用户级"标签，需另行评估（自定义 skill provider 或读工作区目录），P3b/P4 设计时确认。
2. **`.git` 上溯**：projectRoot 是"从 cwd 向上找 `.git`，找不到才回落 cwd 本身"。若用户选择的工作区目录位于某个 git 仓库**内部且不是仓库根**，项目技能将来自**仓库根**的 `.agents/skills`，而非工作区目录的。对 bc「用户自选任意目录当工作区」的产品语义，这是可接受但必须写进用户文档/冒烟的行为（S2b 冒烟建议加一个"工作区在 git 仓库子目录"的负例）。本卡环境无 `.git`，实测 projectRoot=工作区目录本身。
3. **本仓库 `.agents/skills/bc-agent-*` 不被上游发现**：这些 SKILL.md 无 YAML frontmatter（首行是 `#` 标题），被 skill-filesystem 按规则静默跳过——对照组"干净"部分由此而来。这不是作用域失败；但它意味着**本仓库自用的子 agent 角色技能与上游技能格式不兼容**，若未来想让 dsh 会话也看到它们，需补 frontmatter（属产品外决策，仅留痕）。
4. **无 workspaceId 会话的 cwd 兜底 = Host 进程 cwd**（本卡实测=启动目录）。对 Electron 产品这是不可控路径——D7 的"首次启动强制选工作区、不选不进会话"因此是**硬约束**而非体验偏好，前端会话创建流必须总是显式携带 workspaceId（或 cwd）。
5. `workspace.create` 响应是 `{workspace:{...}, created}` 而非裸 `workspaceId`；payload 只认 `path`（`name` 被 strip）。PM 侧既有印象（`{path,name}` → `workspaceId`）需要按 §1.1 修正——adapter 层按真实 schema 收口即可，无行为风险。
