# 2026-08-19 · 定时任务与技能管理落地（模型下拉 / 可读计划 / 启停执行编辑删除 / 技能枚举+编辑卸载+搜索）

## 决策

**定时任务模型下拉**：模型目录走官方 `ctx.connection.api.llm.models({})`（`IApiClient.llm`，会话无关目录，同一 groups 无 per-session 选择；ui-model-selection 同源）。adapter 新增 `listModels` 拍平成 `{provider, model, name}` 选项；创建/编辑表单用 `<select>` 选显示名，写入 `modelName`，空选回退「默认模型」。目录加载失败静默（下拉只剩默认项），满足「实现不了就用默认模型」。

**定时任务列表可读计划（永不给用户看原始 cron）**：`buildCronExpression` 产出 4 种五段 cron，新增 `parseCronExpression` 反解 + `describeCron` 本地化为「每天/每周/每月/每 N 小时」；`cronExpression` 仍落库（P4 调度器消费），UI 只渲染 `describeCron` 结果。

**定时任务四动作**：新增 `cron.tasks.update/delete/run` + `cron.runs.list` 端点（JSON 存 `$DSH_HOME/bc-cron-{tasks,runs}.json`）。启用/停用 = update 的 `enabled` 翻转（`CronTask` 增 `enabled`，旧记录归一化 true）；编辑 = 复用创建弹窗（`parseCronExpression` 预填）；删除 = 共享 `BcConfirmModal` 确认；「执行」= 记录一条手动触发的运行到历史（`CronRun{taskId,taskName,triggeredAt}`），执行记录 tab 渲染。**「执行」语义限定**：P4 前无真实调度/执行引擎，只记录触发事件，不伪造成功/失败状态。

**已安装技能 tab 语义切换**：原「当前会话技能清单」（`listSessionSkills`）改为「本机安装根枚举」——新增 `/ext skills.list`（global `$DSH_HOME/skills` + 每个工作区 `.agents/skills`，client 传入 workspacePaths），每行带 `scope`/`workspacePath`/`installedPath`。原因：官方 `skill.list` 是会话寻址且只读（README：listing is the skill domain's only RPC），无法给出 scope 或卸载句柄。作用域/项目标记在 client 用 `workspaceOptions.items` 把 `workspacePath` 映射成项目标题。

**技能编辑/卸载**：新增 `/ext skills.uninstall`（rmSync 计算路径，`dirname` 守卫拒绝多段 name）与 `/ext skills.edit`（改写 SKILL.md frontmatter 的 `description` 单行字段，`setFrontmatterField` 就地替换或插到 `name:` 后，YAML 安全标量 = 纯 ASCII/CJK 无 `#` 直接写，否则 JSON.stringify）。名称只读（改名 = 目录改名，超出 MVP 范围）。

**搜索与项目筛选**：已安装 tab 顶部工具条 = 搜索框（name/description 模糊过滤）+ 项目下拉（`workspaceOptions.items`；选中某项目 = 全局技能 + 该项目的项目级技能）。搜索无匹配与「还没安装」分离两种空态。

## 验证

`pnpm --filter @bc-agent/capability-core run typecheck|lint` 与 `pnpm --filter @bc-agent/web-ui run typecheck|lint` 全绿。`exactOptionalPropertyTypes` 下 client 侧按条件展开 `workspacePath`；`noUncheckedIndexedAccess` 下 `parseCronExpression` 显式非空索引、`setFrontmatterField` 用 `lines[i] ?? ''`。
