# 2026-08-19 P4-0 cron 执行引擎 + 技能市场（capability-core 合并落地）

## 是什么

capability-core 一次性落地了两大块（文档规划的 capability-cron / capability-skillx 未单独建包，MVP 合并进 capability-core）：

1. **cron 执行引擎**（P4-0）：
   - `cron-parser` v5 调度（`CronExpressionParser.parse` + `CronDate(now,'local')` 本地时区；**具名导入**——该包 CJS 运行时 default 是命名空间对象，default 导入会静默丢 `parse`）；
   - `ctx.interval` 30s tick（cordis timer mixin，**必须进 inject 列表**才能访问）；
   - 到点执行 = 官方 session.create 配方：`session-${uuid}` → `workspaceRegistry.get(id).path` 作 cwd → `ctx.agents.create` → **`agentDefaultModel.currentSelection()` 作 agentOptions（任务未钉模型时，空 options 会让首请求无 provider 而 turn error）** → `workspace.attachSession`；
   - 无人值守权限：`setSandboxMode(session,'workspace-write')` + `setApprovalPolicy(session,'never')`（canonical setter 直设 → custom 派生态，04-spec 决策 18）；
   - 执行记录 JSON 存 `$DSH_HOME/bc-cron-runs.json`（**未按 D4 用 SQLite**——单机量级 JSON 足够，打包期再评估，看板 P4-5 已注记）；
   - 并发保护（running Set）+ 任务不重叠。
2. **技能市场**：`market/skills-market.json`（docs/06-skill-standard §6 配置标准）构建期拷进 lib/；`skills.market.list/install`；GitHub trees API + raw 拉取技能目录 → frontmatter 校验 → 落盘（路径穿越守卫）；`skills.install` 本地安装也加了 frontmatter 校验（P3b-1）。内置 5 个 MIT 技能（obra/superpowers ×3 + addyosmani/agent-skills ×2）；**anthropics/skills 文档技能是 Proprietary 许可（禁止再分发），不收录**。

## 放弃/偏差

- 执行记录用 JSON 而非 D4 规定的自有 SQLite（见上）。
- cron 会话执行后 `handle.dispose()`——live 条目移除、持久化日志保留、workspace 成员槽位保留（侧栏会短暂出现无摘要行，官方投影自动跳过）。
- `apps/desktop` 仍是 Node 启动器，无 Electron（P1-0 后置）。

## 验证

- 冒烟：写入 `* * * * *` 任务 → 调度器 30s 内触发 → 真起会话（DeepSeek 默认模型）→ turn 完成 → 记录 success；修复前（空 agentOptions）记录 failed `turn ended with error`，两条路径都落记录。
- 踩坑记录：PowerShell 写 JSON 带 BOM/单元素解包为对象都会让 loadCronTasks 静默空数组（已加 BOM 剥离）；旧 job_kill 会遗留孤儿 dsh 进程共写 DSH_HOME（清理用进程树，勿只杀 pnpm）。
