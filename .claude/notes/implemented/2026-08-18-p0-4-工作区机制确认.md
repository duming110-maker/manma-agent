# 2026-08-18 · P0-4：工作区机制确认（S6 成立，D7 纯转发定案）

## 决策

**S6 链路上游原生闭环，D7 纯转发定案**：`workspace.create({path})`（canonical path 是注册表成员资格事实源）→ `session.create({workspaceId})`（cwd = 工作区 canonical path，`session.list` 投影逐字节可验）→ 工作区 `.agents/skills`（rank 200）项目技能出现在会话 `skill.list`；对照组（无 workspaceId）不出现；同名项目覆盖用户级（rank asc 首个胜出）；watcher 实时刷新。bc 薄层（P3b capability-workspace）逐字转发 `workspace.*` + `session.create({workspaceId})` 即可，无阻塞缺口。证据链见 `docs/spike/P0-4-工作区机制确认.md`。

**五个语义 surprises 的 PM 裁决**（采纳评审建议）：
1. wire 面 `SkillEntry` 无 rank/source/path → 进 S2b 冒烟前提（断言只打 name/description）+ P3b/P4 设计前提（skillx「项目级/用户级」标签协议面不存在，需自定义 provider 或读目录方案）。
2. **`.git` 上溯**（projectRoot 从 cwd 向上找 `.git`，工作区在 git 仓库子目录时项目技能来自仓库根）→ **必须进用户文档 + S2b 冒烟负例**；对 D7「自选任意目录」语义影响最直接。
3. 无 frontmatter 的 SKILL.md 被静默跳过（含本仓库自用 `bc-agent-*` 技能）→ 留痕即可，产品外决策。
4. 无 workspaceId 会话 cwd 兜底 = Host 进程 cwd（不可控）→ **D7「首次启动强制选工作区」升格为硬约束**；前端会话创建必须显式携带 workspaceId（写进 D7/03-architecture 前置条件）；P1 Electron 化时补审 main.mjs spawn 的 cwd 来源。
5. `workspace.create` payload 只认 `path`（`name` 被 strip）、响应 `{workspace, created}` → P3b adapter 按真实 schema 写契约单测。

**协议事实修正**：frontmatter 可选键是字面 `whenToUse`（camelCase），写 `when-to-use` 会静默丢字段（评审发现，文档已修正）。S2b/S6 冒烟断言禁用总数锚定（用户目录随机器漂移），改 name 集合断言；`.dsh/skills`（rank 100）根冒烟时顺手补用例。
