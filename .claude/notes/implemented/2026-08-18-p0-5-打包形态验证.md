# 2026-08-18 · P0-5：打包形态验证（构建产物 × 官方 loader 闭环）

## 决策

**产物形态定案**：`@bc-agent/web-ui` 的 esbuild 双产物（`lib/index.js` Node 半普通 ESM + `lib/client.js` 浏览器半 `window.__ModuleLoader__.load` 注册壳）满足官方 loader 全部硬契约，零代码改动。证据链三层闭环：服务产物与 `lib/client.js` sha256 字节级一致（服务的即构建产物）；rev 三方一致（`sha1(产物)[0:12]` = roster 行 rev，graph.rev 复算吻合，缓存失效语义正确）；真实浏览器 B1–B6 断言全过（PM 执行：`__ModuleLoader__` 存在、boot entry 在列且无 ui-layout、`__DSH_MODULES__.loadCache` 含我们的包、exports.apply/inject 形状正确、edges 仅 `react/jsx-runtime`、DOM 痕迹俱在）。官方 `ClientModuleSystem` 本体 Node 沙盘 7/7 PASS（开发侧）。

**P1 分发形态（PM 裁决，采纳评审意见）**：倾向「构建 tarball + 首启 `dsh plugin add file:` 安装」；`link:` 保留 dev-only。**补充约束**：tarball 是拷贝语义，`ensurePluginInProfile` 现有存在性 marker 不足以支撑升级——P1 必须以「版本/哈希」为幂等键重装判定。

**`dsh.bundle.patch` 决策（PM 裁决）**：**不加**。维持 `--patch` 叠加通道，组装权留在应用层（与 bc 架构叙述一致）；补 bundle patch 的收益只在「第三方 profile 免 patch 使用 bc 插件」场景，当前无此需求（启动告警留档即可）。

**sourcemap（PM 裁决）**：P1 给 build.mjs 补官方同款 sourcemap（`/plugins/<pkg>/client.js.map` 路由已就绪），并加 `.map` 200 冒烟断言。**红线**：日后若内联任何探测 `process.env`/`import.meta.env` 的依赖，必须先加官方同款 define（tsdown define 三键语义，见 spike 文档）。

**S1 冒烟固化**：A1/A2/A5 静态断言面（产物 200 + sha256 对照 + rev 三方一致 + `.map` 404/未知包 404/POST 405/no-cache 边缘行为）进打包形态回归门，无需浏览器；B6 样式断言必须用 `style[data-bc-web-ui="shell"]`（loader 只认领 factory 期样式，我们是 apply 期自管）；冒烟脚本落地时解决随机端口日志解析与 `ensurePluginBuilt` staleness。
