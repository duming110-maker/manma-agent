# 2026-08-31 · 斜杠菜单技能缓存失效桥（skills/change → agent-preset/selected 重放）

## 是什么

packaged 版已打开的页面里，新安装的技能不出现在 `/` 斜杠菜单（须手动刷新页面）。bc 侧根治：capability-core 新增 `skill-refresh.ts` 桥——监听 Host 事件 `skills/change`，防抖 800ms 后**重放一条真实的** `agent-preset/selected` 事件（在 apiproxy 浏览器转发白名单内），搭载触发客户端技能目录缓存失效。**不改上游任何文件**（dsh 自查给出的"改 api-remotes 白名单 + ui-skill 订阅"方案违反铁律 1，已否决）。

## 上游机制（源码证据链）

1. `dsh-skill`：磁盘 watcher（skill-filesystem，`fs.watchFile` 轮询）→ provider `control.invalidate()` → `invalidateCache()` → `ctx.events.dispatch('emit', ['skills/change'])`（`skill/src/index.ts:650`）。
2. `dsh-api-remotes`：`API_REMOTE_FORWARDED_EVENTS` 白名单（11 个事件，含 `agent-preset/selected`、`commands/change`，**无 `skills/change`**）；apiproxy `api-proxy.ts:3557` 按白名单 `ctx.on` → `host/remote-event` 帧 → 浏览器。
3. 客户端 `ui-skill`：`/` 补全候选 = `source.candidates → fetchCatalog(sessionId)`（**按会话缓存**，无 TTL）；失效入口仅 `agent-preset/selected`（`ctx.remote.$on` → invalidate 全部）与 `connection/reset`。
4. cordis 事件是**全局 hooks 表**（`EventsService.dispatch` 查共享 `_hooks`，无作用域过滤）→ 桥的 `ctx.on` 与任意层级服务的 emit 互通。

## 桥的设计

- 载荷"成对真实"：优先重放本进程监听到的最近一条官方广播 `(sessionId, preset)`（agent-presets 从会话事件流转发的真实值）；无记忆时用任一活跃 agent 的 `sessionId` + `agentPresets.defaultId()`；两者皆缺（无活跃会话）跳过。
- 官方客户端三订阅者对该事件全部幂等/无害：ui-skill invalidate（目的）、ui-commands 目录重拉、ui-agent-preset `noteAgentPreset`（官方注释明说幂等）。
- 防抖 800ms（市场安装多文件落盘会触发一串 skills/change）；debug 日志留诊断锚点。

## 放弃/偏差

- 放弃改上游白名单 + ui-skill 订阅（dsh 自查的方案）：违反铁律 1，且随上游升级丢失。
- 放弃伪造 preset 值：ui-agent-preset 会把假值记到会话行显示；只用真实成对值。
- 放弃 `connection/reset`/`commands/change` 单独方案：前者副作用是全客户端重置；后者只刷新命令目录，不触及 ui-skill 的 `/` 补全 catalog。

## 验证

- 源码级全链闭环（每环均为已验证工作的官方机制，桥只加两根线）：watcher→skills/change ✓、cordis 全局派发 ✓、白名单含目标事件 ✓、三订阅者行为 ✓。
- typecheck ✓；dev host 加载插件无误（wire 注册成功）。
- dev 环境未触发到事件的已解释：**watcher 懒启动**（`list()` 被调用才开始监视根；无会话无人调 list）。用户真实场景有会话（agent 每步调 snapshot）链路必然激活。
- 实机待确认：packaged 新包中，正常会话里装技能后 `/` 菜单应实时出现新技能。

## 踩坑记录
